The workbook identifies possible discrepancies for human review. It does not decide whether a publication is correct or update the website automatically.

Why this workflow matters

Two sources answer two different questions.

Expected state

The scheduled Salesforce report supplies the current internal record: document identifier, approved version, and expected status.

Durable handoff

Power Automate moves the emailed report into SharePoint, giving the Excel workbook a stable place to find the most recent extract.

Observed state

The Python crawler examines the public website and produces a separate Excel extract describing what is actually posted.

Exception-focused review

Refreshing the comparison workbook joins the two outputs and directs people to missing, outdated, or status-mismatched records.

The real workflow uses Salesforce scheduled reporting, email, Power Automate, SharePoint, Excel, and a Python crawler. This reconstruction simplifies the file handling and comparison logic so the design can be shared safely.
